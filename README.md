# Лабораторная работа 1

## Введение в Spring Boot и создание базового проекта

Дисциплина: «Сервис-ориентированное проектирование ПО». КГТУ им. И. Раззакова, кафедра ПОКС.

Цель — настроить Java и PostgreSQL, создать базовое приложение Spring Boot, разобраться в структуре проекта и проверить запуск веб-сервера и подключение к БД.

Проект соответствует первой лабораторной из `Методичка _СОА_26год.docx`: Java 17, Spring Boot 2.7.18, Spring Web, Thymeleaf, Spring Data JPA и PostgreSQL Driver. Созданы пять базовых пакетов и таблица `tasks`. Контроллеры и HTML-представления относятся к лабораторной 2, поэтому здесь приложение остаётся пустым.

## Быстрый запуск на этом компьютере

В терминале откройте папку `lab1` и выполните:

```bash
./scripts/maven.sh spring-boot:run
```

Скрипт выбирает установленную Java 17, загружает локальные настройки из `.env` и запускает Maven Wrapper. Отдельная установка Maven не требуется. PostgreSQL должен быть запущен. База `soa_lab1` и одноимённая роль уже созданы; пароль сохранён только в исключённом из Git файле `.env`.

Откройте http://localhost:8080. Для пустого приложения ожидается **HTTP 404 / Whitelabel Error Page**: сервер работает, но обработчика `/` ещё нет. Признак успешного запуска в консоли — `Started Lab1Application` и сообщение Tomcat о порте 8080. Остановка — `Ctrl+C`.

Если порт занят, измените `SERVER_PORT` в `.env`, например на `8081`.

## Запуск на другом компьютере

1. Установите JDK 17, PostgreSQL и IntelliJ IDEA. Назначьте `JAVA_HOME` каталогу JDK 17, добавьте `$JAVA_HOME/bin` в `PATH`.
2. Скопируйте `.env.example` в `.env` и замените `DB_PASSWORD` своим локальным паролем.
3. Из папки проекта выполните команды ниже (macOS/Linux). `ADMIN_USER` замените именем администратора вашего PostgreSQL.

```bash
set -a
source .env
set +a
psql -X -h 127.0.0.1 -U ADMIN_USER -d postgres \
  -v lab_password="$DB_PASSWORD" -f sql/create-database.sql
./scripts/maven.sh spring-boot:run
```

SQL создаёт роль и БД, если они отсутствуют; пароль существующей роли не меняется. При использовании существующей роли укажите её действительный пароль в `.env`. Таблица создаётся при первом запуске приложения через `schema.sql`, повторный запуск сохраняет данные.

В Windows задайте `JAVA_HOME`, `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` через переменные окружения и используйте `mvnw.cmd spring-boot:run`. Файл `.env` загружается вспомогательным Bash-скриптом, а не самим Spring Boot.

## Открытие в IntelliJ IDEA

На этом компьютере IDE установлена в `~/Applications/IntelliJ IDEA.app`.

1. Выберите **Open** и откройте папку `lab1` либо её `pom.xml` как Maven-проект.
2. В **File → Project Structure → Project SDK** выберите JDK 17. Локальный путь: `/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`.
3. Для Maven Runner также укажите JDK 17 и дождитесь загрузки зависимостей.
4. Самый простой запуск — `./scripts/maven.sh spring-boot:run` во встроенном терминале.
5. Для запуска кнопкой рядом с `main` добавьте переменные из `.env` в **Run Configuration → Environment variables**. Spring Boot самостоятельно этот файл не читает.

## Создание проекта

Основа получена через Spring Initializr с параметрами Maven, Java, JAR, group `kg.kstu`, artifact `lab1`, package `kg.kstu.lab1`, Java 17 и четырьмя зависимостями из методички. На момент выполнения Initializr уже не предлагал Spring Boot 2.7, поэтому после генерации `pom.xml` приведён к версии 2.7.18 и совместимым с ней стартерам.

Версия 2.7.18 выбрана для совместимости с учебными примерами. В последующих лабораторных JPA-аннотации для этой версии импортируются из `javax.persistence`.

## Структура проекта

```text
lab1/
├── pom.xml                         # Версии, зависимости и сборка
├── mvnw / mvnw.cmd                 # Maven Wrapper
├── .mvn/wrapper/                   # Настройки Maven Wrapper
├── .env.example                    # Пример локальной конфигурации
├── scripts/maven.sh                # Выбор JDK, загрузка .env, запуск Maven
├── sql/create-database.sql         # Создание роли и базы
├── src/main/java/kg/kstu/lab1/
│   ├── Lab1Application.java        # Точка входа
│   ├── controller/package-info.java
│   ├── model/package-info.java
│   ├── entity/package-info.java
│   ├── repository/package-info.java
│   └── service/package-info.java
├── src/main/resources/
│   ├── application.properties      # Подключение к БД и параметры сервера
│   └── schema.sql                  # Таблица tasks
└── src/test/java/kg/kstu/lab1/
    └── Lab1ApplicationTests.java    # Проверка HTTP и PostgreSQL
```

Пакеты пока содержат `package-info.java`, чтобы их назначение было документировано и они сохранялись в Git.

| Пакет | Назначение |
| --- | --- |
| `controller` | Принимает HTTP-запросы, вызывает сервисы, возвращает ответ или имя представления |
| `model` | DTO — объекты передачи данных между слоями, не привязанные напрямую к БД |
| `entity` | JPA-сущности, отображаемые на таблицы |
| `repository` | Интерфейсы доступа к данным, обычно наследники `JpaRepository` |
| `service` | Бизнес-логика и координация операций |

## База данных

База: `soa_lab1`. Таблица: `public.tasks`. Кодировка UTF-8 поддерживает русский текст.

| Поле | Тип PostgreSQL | Ограничения и назначение |
| --- | --- | --- |
| `id` | `BIGINT` | Первичный ключ, `NOT NULL`, генерация `IDENTITY` |
| `name` | `VARCHAR(255)` | Название, допускает `NULL` |
| `description` | `TEXT` | Длинное описание, допускает `NULL` |
| `due_date` | `DATE` | Срок выполнения, допускает `NULL` |
| `completed` | `BOOLEAN` | Признак выполнения, допускает `NULL` |

На скриншоте методички приведены SQL Server-типы `nvarchar(255)`, `nvarchar(MAX)` и `bit`. Для требуемого PostgreSQL использованы `VARCHAR(255)`, `TEXT` и `BOOLEAN`. Допустимость `NULL` сохранена по скриншоту. Генерация идентификатора добавлена для удобства вставки новых задач.

`spring.sql.init.mode=always` запускает `schema.sql`. `CREATE TABLE IF NOT EXISTS` не удаляет существующую таблицу. `spring.jpa.hibernate.ddl-auto=none` оставляет управление схемой SQL-скрипту. Сущности и репозитории в первой лабораторной ещё не реализуются.

Проверка структуры:

```bash
psql -h 127.0.0.1 -U soa_lab1 -d soa_lab1 -c '\d tasks'
```

## Тестирование и сборка

```bash
./scripts/maven.sh verify
```

Тесты используют настоящую PostgreSQL из `.env`, поднимают приложение на случайном свободном порте и проверяют:

- запуск Spring-контекста и встроенного Tomcat; ожидаемый HTTP 404 для пустого приложения;
- вставку задачи с автоматически созданным `id`, кириллицей, описанием длиннее 255 символов, датой и логическим полем;
- чтение значений, изменение `completed` и удаление тестовой записи.

Тест изменения данных выполняется в транзакции с автоматическим откатом. Значения последовательности `id` после отката могут иметь пропуски — это нормальное поведение PostgreSQL.

После успешной сборки JAR находится в `target/lab1-0.0.1-SNAPSHOT.jar`. Для самостоятельного запуска JAR сначала экспортируйте переменные из `.env`, затем выполните:

```bash
set -a
source .env
set +a
"/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home/bin/java" \
  -jar target/lab1-0.0.1-SNAPSHOT.jar
```

На другом компьютере используйте `java` из установленного JDK 17.

## Основные понятия для защиты

**Spring Framework** предоставляет контейнер объектов и инфраструктуру приложения. **IoC** означает, что жизненным циклом компонентов управляет контейнер. **DI** — способ реализации IoC: необходимые зависимости передаются объекту извне, например через конструктор.

**Spring Boot** упрощает запуск Spring-приложения благодаря стартерам, автоконфигурации и встроенному веб-серверу. Стартер объединяет совместимые зависимости. Автоконфигурация выбирает настройки на основании доступных библиотек и свойств приложения.

**`@SpringBootApplication`** объединяет конфигурацию приложения, включение автоконфигурации и поиск компонентов. Метод `SpringApplication.run(...)` создаёт контекст Spring и запускает приложение. Главный класс расположен над остальными пакетами, чтобы поиск компонентов охватывал их.

**Spring MVC** разделяет модель, представление и контроллер. `@Controller` обрабатывает запросы и может возвращать имя HTML-шаблона; `@RestController` возвращает тело HTTP-ответа. `@Service` обозначает компонент бизнес-логики. `JpaRepository` предоставляет операции доступа к данным.

**Thymeleaf** формирует HTML на сервере. Контроллер передаёт данные в `Model`, шаблон выводит их через атрибуты, например `th:text`. Зависимость подключена в первой лабораторной; создание контроллера и шаблона предусмотрено второй.

**JPA** — спецификация объектно-реляционного отображения. Hibernate реализует её, а Spring Data JPA упрощает создание репозиториев. PostgreSQL Driver обеспечивает JDBC-соединение с PostgreSQL.

**Java 17** — LTS-версия Java. Уточнение к теории методички: sealed classes в Java 17 уже окончательная возможность языка, а pattern matching для `switch` в Java 17 имел статус preview. Для этой работы preview-возможности не используются.
